02

RUN

Search something real.

The demo builds a local index and returns ranked matches. Its deterministic token-count features require no pretrained model. Bring your own embeddings for your application.

Start with the bundled corpus. Results are lexical matches from hashed token counts.

TERMINAL / LOCAL SEARCH
kd workload demo

Uses a compatible bundled artifact if present, otherwise the compiled MLX fallback. Override with --artifact PATH.

Use the callable in Python +
APPLICATION API
from kerneldarwin.fused_search import FusedPlan
from kerneldarwin.search import text_vectors

plan = FusedPlan()  # complete compiled MLX fallback
documents = ["Metal kernel", "cosine vector search", "CPU control"]
index = plan.index(text_vectors(documents))
ids, scores = index.search(text_vectors(["vector search"]), k=2)
print([(documents[i], score) for i, score in zip(ids[0], scores[0])])
print(plan.last_decision)

To install an exported plan, replace the first line of setup with plan = FusedPlan("artifact"). Invalid or stale plans select the library fallback.

Read the kernel and semantic contract +

score_simd.metal · authored source excerpt

const long query_base = long(query) * long(queries_strides[0]);
// Each read uses the actual device strides.
const float value = column < D
    ? queries[query_base + long(column) * long(queries_strides[1])]
    : 0.0f;
  • Float32 accumulation with stable maximum scaling.
  • Denominator clamped at 1e-12; zero rows stay zero.
  • Any NaN or infinity makes the entire output row NaN.
  • Float16 and bfloat16 use the library fallback.
  • Only two-dimensional MLX arrays; inference only.

A confirmed scoring export would contain manifest.json, score_simd.metal and score_tile4.metal. No plan passed the performance gates in this investigation. Source and environment must match before a rule can run.
