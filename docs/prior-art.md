# Prior art and reuse decisions

Reviewed against primary project documentation and papers on **26 October 2026**. These are source reports, not replications. Repository `main` branches and documentation are mutable; a future comparison must pin revisions and environment versions. No upstream benchmark score is a KERNELDARWIN result.

| Foundation | What already exists | Consequence for this project |
|---|---|---|
| [KernelBench](https://github.com/ScalingIntelligence/KernelBench), [paper](https://arxiv.org/abs/2502.10517) | A 250-workload PyTorch kernel benchmark, correctness/performance evaluation and the `fast_p` success metric. MIT code license. | Useful evaluation precedent. Its tasks and reported model scores are not proof that our four operation families are representative. No task sources are vendored. |
| [Meta KernelAgent](https://github.com/meta-pytorch/KernelAgent) | Hardware-guided optimization, multi-worker Triton synthesis, runtime verification and composition into a complete forward pass. Apache-2.0. Its documented setup needs GPU/software and a model provider. | Profile-guided agent optimization and usable kernel composition are established capabilities, not our novelty. No provider-backed service is required by our bounded implementation. |
| [Kernel Forge paper](https://arxiv.org/abs/2607.24762), [code](https://github.com/TheJoshBrod/KernelForge) | Operator profiling, agent kernel generation, Monte Carlo Tree Search, inspection GUI and in-place model integration; the paper evaluates four models on GB10. MIT code. | Agentic candidate search, a GUI and end-to-end integration are established. Published speedups are tied to that setup; we have not reproduced them. |
| [Triton](https://github.com/triton-lang/triton), [autotune API](https://triton-lang.org/main/python-api/generated/triton.autotune.html) | Tiled GPU compiler and configuration autotuning with optional pruning, performance models and custom benchmarking. MIT. Upstream currently lists Linux and NVIDIA compute capability 8.0+ for its NVIDIA backend. | Reuse the compiler and compare against actual Triton autotuning. Ranking the same configurations is not a new compiler. An interpreter run is not a CUDA performance measurement. |
| [PyTorch](https://github.com/pytorch/pytorch), [compiler docs](https://docs.pytorch.org/docs/stable/torch.compiler.html) | Tensor semantics, eager execution and compiled program execution, including Inductor. PyTorch's license contains its own BSD-style terms and historical component notices. | Use declared eager references and report a compiled baseline separately. Do not compare only against a weak hand-written baseline. Preserve the installed distribution's notices. |
| [NVIDIA Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/) | Hardware-counter collection, roofline analysis, replay modes, and clock/cache controls. NVIDIA tooling has separate terms. | Use mature profiling tools rather than rebuilding them. Counter collection may replay execution and alter conditions, so measure latency separately. Do not infer occupancy from latency alone. |
| [CUDA Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/) | `memcheck`, `racecheck`, `initcheck` and `synccheck` target distinct error classes. Racecheck focuses on shared-memory hazards. NVIDIA terms apply. | An available sanitizer result is additional evidence. A skipped tool, passing numerical test or passing racecheck alone does not establish memory safety. |
| [BoTorch](https://github.com/meta-pytorch/botorch) | Modular Bayesian optimization using probabilistic models and acquisition functions, built on PyTorch. MIT. | A useful optional research baseline; introducing its dependency tree is unnecessary for the basic explorer or compact selector. A ridge uncertainty score is not a BoTorch comparison. |
| [AutoTVM](https://arxiv.org/abs/1805.08166), [Ansor](https://arxiv.org/abs/2006.06762) | Learned tensor-program cost models and transfer predate this project; Ansor combines learned ranking, evolutionary search and task scheduling. | Learned intervention ranking alone is not a novel research contribution. Demonstrate a measurable benefit from explicit diagnosis and controlled experiments, or report that it does not help. |
| [KTT](https://github.com/HiPerCoRe/KTT), [counter-guided tuning data paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC8633859/) | KTT supports correctness checking, dynamic autotuning and counter/ML-guided search. Its historical dataset contains measured CUDA tuning spaces from five benchmark types and four GPUs. | Even counter-guided learned search has close precedents. Historical replay is an optional distinct evaluation route, not current-device replication. KTT code is MIT; the [dataset](https://data.mendeley.com/datasets/nn53dskr7z/1) is CC BY 4.0. No data are bundled here. |

## Visual-production tools investigated

[PaperVizAgent](https://github.com/google-research/papervizagent), formerly PaperBanana, is the official reference-driven academic-illustration pipeline, with retrieval, planning, styling, rendering and critique agents. The code is Apache-2.0; its documented configuration uses model API credentials or Google Cloud settings. It was inspected, not executed. Editable authored SVG diagrams avoid a separately billed API and keep technical labels reviewable. Numerical plots must always be generated from experiment data.

[/brag](https://github.com/latent-spaces/brag) is an MIT-licensed agent skill for short product launch videos, using Hyperframes in its regular workflow. It is available in the local skill installation. The release presentation can use that free local workflow; any footage must identify CPU controls or recorded playback and must not imply a live CUDA optimization on this host. Tool availability is not evidence of a successful video render.
