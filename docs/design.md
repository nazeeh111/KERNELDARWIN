# KERNELDARWIN LAB design

The LAB is a read-only scientific instrument. An ivory paper field, dark ink, vermilion evidence accent and a compact fixed navigation establish an editorial laboratory identity. The original K/D mark echoes a branching intervention. System sans-serif typography supports prose; system monospace marks units, identifiers and reproducibility details. No external fonts, analytics or JavaScript dependencies are requested.

The interface has eight views: performance overview, recorded execution timeline, bottleneck explorer, hypothesis laboratory, optimization evolution, source comparison, searchable atlas, and research results. Data comes from `lab/data/index.json` or a local JSON import. Source is rendered as text. Imported records never execute source code.

Every quantitative chart derives from input samples. The latency distribution is a histogram with explicit microsecond units and sample counts. GPU traces require actual timestamped duration events. Hardware counters retain their original names and units. An unavailable roofline stays empty rather than substituting illustrative measurements. GPU and CPU evidence are visibly distinguished. A CPU control record cannot establish a CUDA speedup or a GPU policy result.

Imports accept version 1 records with explicit evidence type and supported workload metadata. Failed imports preserve the current investigation. Imports are memory-only; exporting downloads the current record. Local file import has a 20 MB limit. Manifest records must share the page origin. This viewer is an inspection tool, not a cryptographic verifier of record provenance; use CLI validation and inspect the provenance before relying on imported claims.

Keyboard navigation, a skip link, visible focus, native controls, readable error messages and no required motion support accessibility. The sidebar becomes a horizontally scrollable view navigation below 900 px. Main panels stack on narrow displays. The default source is shipped with no fabricated benchmark records.

Serve the `lab` folder through the CLI or any static HTTP server. Opening `index.html` as a local file supports import, but browser security may prevent fetching the bundled manifest.

## Current-source browser verification

Native Google Chrome through a temporary Playwright profile rendered the real CPU softmax control record at 1440 × 1080 and 390 × 844. All eight views rendered with zero JavaScript page errors and no document horizontal overflow. The initial mobile check caught the navigation's intrinsic grid width; the corrected shrinkable grid passed the repeated check. Invalid JSON import preserved the current record, valid import succeeded, and native Tab reached the visible skip-navigation link. Overview statistics and distribution use the accepted winner's independent confirmation samples and confidence interval together, rather than mixing discovery and confirmation timings. Screenshots are in `docs/assets/lab-*.png`. This check is functional and visual QA, not a full accessibility conformance audit.

The shipped manifest selects four exact CPU suite records: softmax 128 × 1024, a sum 32 × 31 case with no accepted improvement, a stride-2 layernorm case, and a fused elementwise case. Its optional `evaluation` URL loads compact policy-evaluation aggregates. Research controls compare held-out family/shape splits at equal candidate budgets; charts use measured mean log-speedup reward, with a table of observed workload counts, oracle gaps and experiment costs. The raw suite remains the reproducibility source. The importer checks accepted winners against raw discovery and independent confirmation pairs, the declared improvement threshold, correctness status and GPU provenance declarations. These are consistency checks; no JSON-only viewer can authenticate hardware execution.

Final-source QA additionally verified five rejected malformed imports (null experiment, null hypothesis, null configuration, missing independent confirmation, false GPU provenance), preserved subsequent evolution navigation, searchable Atlas evidence filtering, family/shape and candidate-budget evaluation controls, and an exported JSON round trip. `docs/assets/lab-qa.json` records the passing checks and SHA-256 identities of the rendered sources and bundled records. Screenshots were refreshed from the final four-record suite and the 72-observation evaluation including the sequential GP-UCB baseline. Phone chart geometry preserves readable labels rather than shrinking a desktop plot. This is software/visual evidence only, with no claim of GPU execution or full accessibility certification.
